# Product Category Table

Табличный вывод товаров WooCommerce на странице категории — по образцу
`anepmetall.ru/katalog/.../krug-nergaveyuschij/`: быстрые кнопки-фильтры сверху,
блок «Фильтр продукции» с выпадающими списками по атрибутам, сортируемая таблица
(Наименование, характеристики, Цена), кнопки «Заказать» / «Узнать цену», пагинация,
плавающая корзина на всех страницах сайта.

Это отдельный плагин, написанный с нуля — не доработка `anep-woo-table`. Причина:
`anep-woo-table` на большой категории (много подкатегорий, много товаров) валил сайт
в `Fatal error: Allowed memory size exhausted`, потому что строил список фильтров и
индекс для сортировки, вызывая `wc_get_product()` в цикле по **всем** товарам ветки
категории (и по всем вариациям каждого товара). Здесь эта схема исключена архитектурно.

## Как это работает и почему не должно упасть по памяти

- Список товаров категории (с учётом всех подкатегорий) получается через обычный
  `WP_Query` с `'fields' => 'ids'` — это просто числа, не объекты. WordPress сам
  разворачивает дерево категорий (`include_children`), отдельный обход подкатегорий
  не нужен.
- Значения для фильтров и для быстрых кнопок сверху берутся через
  `get_terms( array( 'object_ids' => $ids ) )` — это JOIN по таблице связей термов,
  а не перебор товаров в PHP.
- Сортировка по колонке-атрибуту (Марка, Диаметр и т.д.) сделана через `posts_clauses`
  и обычный SQL `JOIN` + `ORDER BY` — сортирует MySQL, а не PHP-цикл.
- `wc_get_product()` вызывается только для товаров **текущей страницы таблицы**
  (по умолчанию 20, не больше 200) — ровно так же, как это делает обычная страница
  каталога WooCommerce. Он никогда не вызывается для всей ветки категории.

Итог: категория с большим деревом подкатегорий и тысячами товаров нагружает сервер
так же, как обычная страница каталога WooCommerce — не больше.

## Требование к товарам

Характеристики читаются в двух вариантах — плагин поддерживает оба одновременно,
включая на одном и том же сайте (одна категория может использовать один тип, другая —
другой):

1. **Глобальные атрибуты WooCommerce** (`pa_*`, Товары → Атрибуты), назначенные прямо
   на товар — через taxonomy, `get_terms()`/`tax_query`.
2. **Локальные атрибуты товара** — то, что WooCommerce выводит на вкладке
   «Дополнительная информация»/«Детали» карточки, когда атрибут добавлен прямо на товар
   и не привязан к глобальной таксономии (самый частый способ у парсеров/импортёров,
   потому что не требует заранее заводить атрибут в Товары → Атрибуты). Такие значения
   плагин зеркалирует в собственный postmeta (класс `PCT_Attributes`) при каждом
   сохранении товара, и после этого фильтрует/сортирует их обычным SQL
   (`meta_query`/`orderby=meta_value`) — тоже без перебора товаров.

Плагин **не** умеет читать значения, которые есть только в вариациях, но не
продублированы на родительском товаре (для простых товаров, что чаще всего и нужно
для прайса «одна строка = один реальный товар», это не ограничение).

**Важно про уже импортированные товары.** Локальные атрибуты подхватываются
автоматически только при сохранении товара (хук `save_post_product`) — то есть сами
собой это сработает только для товаров, сохранённых ПОСЛЕ установки/обновления
плагина. Для всех, что уже в базе, один раз нажмите **«Пересканировать все товары»**
на странице настроек (WooCommerce → Category Table) — обрабатывает магазин пакетами
по 200 товаров через AJAX, безопасно для любого размера каталога. Если этого не
сделать — фильтры для категорий с локальными атрибутами останутся пустыми, даже
если на карточке товара характеристики видны.

## Фильтры и колонки — по умолчанию автоматические, для каждой категории свои

Плагин **не** использует один и тот же фиксированный список фильтров для всех
категорий. При открытии категории он смотрит, какие атрибуты (и глобальные `pa_*`, и
локальные — оба типа) реально назначены хотя бы одному товару в этой категории (с
учётом подкатегорий), и показывает фильтром/колонкой только их:

- категория «Круг нержавеющий» → Марка, Диаметр, ГОСТ/ТУ, Покрытие, Технология
  изготовления (что реально заполнено у товаров именно этой категории);
- категория «Лист перфорированный» → Марка, Толщина, Покрытие, Тип, Технология
  изготовления;
- категория, где у товаров есть Длина/Ширина/Толщина, — покажет именно их, даже
  если в настройках плагина они нигде явно не перечислены.

Технически: для каждого зарегистрированного атрибута (и глобального, и локального)
выполняется один дешёвый запрос «есть ли хоть одно значение у товаров этой категории»
(`get_terms(object_ids=>...)` / `SELECT 1 ... LIMIT 1`) — не перебор товаров. Результат
кешируется на категорию и сбрасывается при изменении товаров/категорий.

Поля «Фильтры»/«Колонки таблицы» в настройках — это **принудительное** переопределение
(один и тот же список сразу для всех категорий). Если оставить их пустыми (по
умолчанию) — работает автоопределение выше. На странице настроек также видно, сколько
и каких атрибутов (глобальных/локальных) плагин вообще нашёл в магазине — полезно для
диагностики, если фильтры не появляются.

## Настройка

WooCommerce → Category Table:

- принудительный список фильтров/колонок (необязательно — по умолчанию автоопределение
  по категории, см. выше) и лимиты на их количество (0 — без ограничения);
- сколько товаров на странице;
- атрибут для быстрых кнопок (chips) и сколько показывать до «Смотреть все»;
- префикс/единица цены («от » + «355» + «руб./кг»);
- подписи кнопок «Заказать» / «Узнать цену»;
- включена ли плавающая корзина;
- email и обязательность телефона для заявок «Узнать цену»;
- дата «Сортамент товаров актуализирован: …» — обновляется вручную (например, после
  каждого запуска парсера).

## Кнопка «Заказать» и плавающая корзина

«Заказать» использует стандартный AJAX WooCommerce (`wc-add-to-cart.js` +
`wc-cart-fragments`) — без своего JS-обработчика добавления в корзину, товар
добавляется в обычную сессионную корзину `WC()->cart`. Показывается, если товар
purchasable, в наличии и имеет цену. Иначе показывается «Узнать цену» — открывает
модалку с формой (имя, телефон), заявка уходит на email из настроек через `wp_mail()`
(если на сервере нет настроенного SMTP, поставьте отдельный SMTP-плагин, иначе письма
может резать хостинг).

Плавающая кнопка корзины (левый нижний угол, чтобы не перекрывать чат-виджеты в
правом) показывается на всех страницах сайта — покупатель может переходить между
категориями, всё добавленное копится в одной корзине WooCommerce. Клик открывает
выезжающую панель: можно изменить количество или удалить позицию (AJAX, без
перезагрузки), внизу — форма «Имя» + «Телефон». Отправка формы создаёт обычный заказ
WooCommerce (`wc_create_order()`, статус `on-hold`, оплата «Быстрый заказ»), поэтому:

- заказ сразу виден в WooCommerce → Заказы;
- админу уходит штатное письмо WooCommerce «Новый заказ» (настраивается в
  WooCommerce → Настройки → Email, отдельного email здесь для этого не нужно);
- никакой отдельной формы оплаты/доставки не запрашивается — это осознанно упрощённый
  «быстрый заказ», обработка (созвон, счёт и т.д.) — вручную по заказу в админке.

## Шорткод

```
[product_category_table]                          — текущая категория (внутри архива)
[product_category_table category="krug-nerzhaveyushchij"]
[product_category_table category="all"]
```

## Чего здесь нет (сознательно, чтобы не раздувать плагин)

- Виджета Elementor — если нужен, его можно добавить поверх `PCT_Render::render_table()`.
- Динамических live-обновляемых счётчиков «сколько товаров у каждого значения фильтра»
  прямо в `<option>` — можно добавить, но это лишний запрос на каждый пункт списка;
  сейчас список значений фильтра уже учитывает остальные выбранные фильтры (Excel-логика),
  просто без чисел в скобках.
- Полной формы оформления заказа (адрес доставки, способ оплаты, промокоды) — только
  быстрый заказ по имени и телефону, см. выше. Если нужен полный чекаут, можно вместо
  формы в панели корзины сделать ссылку на обычную страницу `/checkout/` WooCommerce.

## Changelog

**1.2.1** — фикс: выбор значения в фильтре уводил на другой URL (в частности, на
главную), если категория собрана отдельной страницей/Elementor-страницей с шорткодом
`[product_category_table]`, а не через нативный архив категории WooCommerce. Причина —
форма фильтров/сортировка/пагинация отправлялись на `get_term_link($term)` (адрес
архива термина), а не на реально открытую страницу. Теперь во всех случаях используется
текущий URL страницы.

**1.2.0** — поддержка локальных (не-taxonomy) атрибутов товара наравне с глобальными
`pa_*`: автоопределение фильтров/колонок, фильтрация (`meta_query`) и сортировка
(`orderby=meta_value`) теперь работают и для характеристик, назначенных прямо на товар
без глобальной таксономии — то есть для типичного результата импорта парсером. Значения
зеркалируются в postmeta при каждом сохранении товара; для уже существующих товаров на
странице настроек есть кнопка «Пересканировать все товары» (пакетами по 200, AJAX).
Страница настроек также показывает, сколько и каких атрибутов найдено — для диагностики.

**1.1.0** — фильтры/колонки теперь определяются автоматически по атрибутам, реально
назначенным товарам конкретной категории (у разных категорий — разный набор), вместо
одного фиксированного списка на все категории. Кнопка «Купить» переименована в
«Заказать» и добавлена плавающая корзина (AJAX-добавление без перезагрузки, копится
при переходах между категориями, оформление заказа по имени/телефону создаёт обычный
заказ WooCommerce).

**1.0.0** — первая версия.
